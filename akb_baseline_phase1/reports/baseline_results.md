## Phase 1 completion questions

1. Can SciFact be evaluated locally with a strong public verifier without training? **Yes. MultiVerS inference and official evaluation pass; the published checkpoint's dev score is split-contaminated and should be used only as pipeline validation.**
2. Can SciFact-Open be evaluated on the full 500K corpus with a reproducible retrieval baseline? **Yes. A standard Okapi BM25 index (k1=1.5, b=0.75, English stopwords removed) was built over the full 500K corpus in 138.3 sec and retrieved top-100 documents for all 279 claims in 3.9 sec. Recall@1/5/10/50/100 = 0.3575 / 0.5772 / 0.6495 / 0.7886 / 0.8552 against gold evidence documents (206/279 claims have evidence; NEI claims excluded). A 5-claim sanity sample confirmed doc_id integrity against the corpus.**
3. Can retrieval output be transformed into a verifier/AKB-compatible interface with a thin adapter? **Yes, and demonstrated end-to-end. SciFact-Open's `corpus.jsonl` already matches MultiVerS's `{doc_id, title, abstract}` schema, so the adapter only needed to convert each claim + its BM25 top-K doc_ids into MultiVerS's `{id, claim, doc_ids}` input format. The full 279-claim run (top-10) completed in the existing `akb-multivers` environment with no changes to either pinned author repository, giving document-level verification F1 0.4265 (retrieval-capped) / recall 0.6054 once a gold document is actually retrieved.**
4. Which baseline should remain fixed when AKB is introduced? **A combination: MultiVerS as the fixed document-level verifier (its SciFact dev numbers are pipeline validation only, not a clean generalization estimate - see the contamination note below), and BM25 as the fixed open-domain retrieval baseline for SciFact-Open, since a thin, unmodified adapter already connects the two. AKB's natural insertion point for Phase 2 is upstream of MultiVerS - improving or replacing the retrieval/evidence-selection stage feeding it - while MultiVerS's verification call and both evaluators stay fixed so results remain comparable across phases.**
